# Production canvas, image preparation and autosave — 1.1.8-yd.4.5

The production canvas could report saved director planning and storyboard rows without refreshing their text nodes. Image preparation could reserve several storyboard targets and then abort on a later missing reference, leaving the earlier cards permanently generating. A selected 4K size was also incompatible with the registered Seedream adapter, but was rejected only after reservation.

This release connects structured model streaming to read-only canvas previews for director planning and the storyboard table. Previews are explicitly unsaved and never enter autosave. Final structured validation and server commits remain authoritative; failed/cancelled output does not overwrite prior work. Artifact refreshes now update planning text and planning versions as well as assets/cards, and polling drains paginated terminal events.

It also fixes an omitted Web entry point in yd.4.4: the shared frontend store was still injecting the legacy 12,000-token total. Normal production starts now actually omit that field and use independent model calls; explicit legacy API totals remain supported. The composer displays running status and its stop action cancels the durable run.

Full derived-asset production with image authorization selects both description analysis and image generation. Already registered children without pictures are included even if analysis creates no new descriptions. Description-only completion is reported explicitly; image artifacts are emitted only after actual generation. Image and video counts still require their existing authorization.

Image batches validate missing reference images before reserving anything, identify the missing assets by name, and release earlier unsubmitted reservations if later preparation fails. Configured image sizes are checked before reservation/provider submission. Preview/download endpoints validate project ownership and image availability, return errors on unreadable/empty images, and handle tiny images without oversized label overlays. The browser prevents empty/null previews and always releases loading state.

Image quality choices come from registered model resolutions, with the Seedance NZ Seedream capability narrowed to 1K/2K, consistent with the [provider documentation](https://api.seedance.nz/docs/). Explicit resolutions metadata is honored for other vendors; older vendor templates retain their declared legacy ImageConfig quality contract. Backend project validation and generation preflight use these capabilities too. Video quality choices follow all duration/resolution combinations, and duration selection uses actual supported values rather than a continuous min/max range. Per-user video options are remembered locally; fixed audio capability is enforced in the UI.

Canvas script, director-plan and storyboard-table editors autosave with version checks. Script edits now use the real script update endpoint rather than the planning-only endpoint. Image graph edits use serialized, versioned autosaves; unselected draft graph pointers are scoped to the browser user/project/episode/target so reopening can recover the draft. Selecting an image remains a separate choice: generated/uploaded media is already saved, and the button is labeled accordingly. Conflicts preserve drafts instead of overwriting another editor's changes.

Operational repair: 15 specifically identified RESERVED jobs with no upstream task ID were backed up and failed, allowing existing recovery logic to release their storyboard claims. No submitted provider task was replayed. The affected project's invalid 4K setting was changed to 2K through the versioned project service, with a backup and idempotent mutation record.

Validation: 272 backend tests passed, with zero failures/skips; final focused checks and both TypeScript builds passed. PostgreSQL regressions cover batch preflight/rollback, capability rejection before provider calls, existing unpictured derived assets, and preview-before-commit. SDK tests exercise real structured streaming and length truncation. Browser acceptance passed against the compiled application: cookie-authenticated Web starts, live canvas previews, automatic updates, autosave persistence, draft restoration after reload, quality filtering, and empty-preview failure handling with simulated providers. No paid generation is part of these regression tests.
