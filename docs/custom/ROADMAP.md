## 下一阶段执行顺序

### P0：先完成零付费生产验收

1. **人 ↔ Agent 完整交接（T27 / T28 / T32）**
   - 在真实 Web 中完成问题 → 人工回答 → Agent 续做。
   - 完成暂停 / 恢复、人工 takeover / Agent 再接手。
   - 验证同一运行只出现一个入口，不重复创建 run、step、artifact 或任务。
   - 项目页必须能同时看到已完成内容、候选结果、待回答问题和下一步动作。

2. **真实生产上传与媒体链路（T07 / T08 / T16）**
   - 使用真实图片、视频、音频文件完成上传、预览、Range、缩略图和权限检查。
   - 验证文件确实落在当前配置的 NAS，并在浏览器刷新/重新登录后仍能访问。
   - 图片编辑流完成一次真实 Web ↔ NAS round trip；不得触发额外模型调用。

3. **审核、返工与同资源人工接手（T19 / T29 / T30 / T33）**
   - 候选选择 → 定稿 → 返工 → 再定稿完整走一遍。
   - Agent 正在处理时人工 takeover，同一资源的晚到结果不得覆盖人工的新版本。
   - 修改依赖素材后，只阻止受影响提交；无关分镜/素材任务应继续执行。
   - 验证人机混合并行时同资源 CAS/锁冲突清晰，不同资源可继续工作。

### P1：需要真实模型调用的质量验收

4. **创作链路质量（T04 / T06 / T12 / T13 / T15 / T36）**
   - 原文事件提取与改编。
   - 剧本素材提取。
   - 音频匹配。
   - 导演规划。
   - 分镜/素材图片生成与检查。
   - 至少一组多角色、多镜头连续性样例。

   这些步骤会产生真实模型费用。未取得明确的付费测试授权和额度前，只允许做读取、契约、模拟和既有结果复用，不得主动发起新的付费生成。

5. **Seedance 2.5 其余五个 Standard 变体**
   - 国内/国际 T2V、I2V、Multi 六类中，国内 Standard T2V 已完成一次真实付费验收。
   - 其余五个变体分别做最小额度的真实输出验收时，必须记录请求参数、上游 task ID、持久 job ID、输出规格、NAS/HTTPS 校验和实际费用。
   - 不允许用一个成功样例推断其他变体已经通过。

### P2：维护窗口内的故障演练

6. **真实 NAS / 网络故障恢复（T23）**
   - 仅在明确维护窗口执行真实 NAS 或网络中断。
   - 目标是验证正在运行的应用拒绝错误媒体根目录、不会写入本地 fallback，重新挂载后能够继续读取既有媒体。
   - 不为了补测试记录而对活跃用户工作做破坏性演练。

## 固定边界

- 不引入 TF-Router 或额外队列平台。
- 不增加服务端最终成片渲染；最终导出继续使用现有浏览器 WebAV 路径。
- 保持 Seedance 2.0 旧模型和旧插件兼容，不把图片任务与视频任务混用。
- 不重置现有管理员账号、provider credential、custom-model 或 enabled-state。
- 所有生产验收必须留下可复核的 run/job/task ID、版本、文件哈希或浏览器结果；`LOCAL VERIFIED` 不能替代 `PROD/LIVE VERIFIED`。

每完成一组生产验收，先更新 `BUILTIN-IMPLEMENTATION.md` 的对应 T 项状态，再补充 `BUILTIN-RELEASE.md` 的具体实证；不要仅修改本路线图来宣称完成。
